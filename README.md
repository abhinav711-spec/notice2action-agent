# Notice2Action

**Turn public and academic notices into evidence-linked next steps.**

Notice2Action is a self-contained Python application for reading a text-based PDF notice, locating a limited set of dates and requirements, checking quotes against their cited pages, reviewing a supplied applicant profile, and preparing an action list.

Its differentiator is **Notice Watch**: save extracted versions in your browser and compare an amendment with an earlier notice. A deterministic Python diff reports changed or added rules with evidence from both versions. It does not depend on a model prompt to remember prior documents.

## What it does

- Accepts PDF files up to 5 MB and 25 pages.
- Extracts selectable text locally; scanned-image OCR is not included.
- Uses bounded Python patterns for common dates, GPA/income thresholds, fees, contact details, and required documents.
- Verifies extracted quotes on their cited PDF page; unverified claims are quarantined from profile comparison and Notice Watch.
- Compares recognized requirements with optional profile details.
- Produces a reviewable checklist, dated calendar events, bilingual briefing, and draft clarification email.
- Saves structured notice snapshots in browser-local storage; compares only verified claims and displays both source quotes and page numbers.
- Provides a responsive, keyboard-operable UI with no third-party UI CDN.

The local extractor intentionally leaves unsupported requirements blank. A missing result is not proof that the original notice has no such requirement.

## Run locally

Requirements: Python 3.11 or newer.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pytest -q
python -m uvicorn app.main:app --reload
```

Open [http://127.0.0.1:8000](http://127.0.0.1:8000). Use the sample workflow or provide a selectable-text PDF. API documentation is available at `/docs`.

No model API key or external AI service is required. The demo document is explicitly fictional.

## Notice Watch data and privacy

Snapshots (title, extracted fields, quotes, verified claim IDs, version label, and save time) remain in the current browser's local storage. PDFs, applicant profiles, email drafts, and full document text are not saved by Notice Watch.

Comparing two saved versions sends those structured snapshots to this app's stateless `POST /api/watch/compare` endpoint for one request. The API does not persist them. History does not sync to another browser or device and can be removed with **Clear local history** or by clearing browser storage.

When using a hosted instance, the PDF is uploaded to that instance for processing. The app does not intentionally save uploaded PDFs or applicant profiles, but review the host's logging and retention policies before uploading sensitive documents.

## Trust and limitations

- Quote presence proves only that similar text appears on a cited page; it does not prove that the interpretation is correct or that all exceptions were found.
- Eligibility results are an aid, not an official decision or legal advice.
- Dates are included in calendar exports only when the local parser can normalize an explicit date.
- The engine uses conservative local patterns rather than an LLM. Unusual layouts, tables, scanned PDFs, and complex legal language may require manual review.
- Instruction-like text in a notice is treated as untrusted document content and never executed.

## API

| Route | Purpose |
|---|---|
| `GET /api/health` | Service and extraction-engine health |
| `POST /api/process` | Analyze a PDF and optional JSON applicant profile |
| `GET /api/demo-conflict` | Run the fictional sample notice against a demonstration profile |
| `POST /api/watch/compare` | Compare two saved notice snapshots and return evidence-linked changes |
| `GET /api/calendar/ics/{notice_id}` | Download the calendar generated by a recent analysis |
| `GET /api/sample/download-pdf` | Download the fictional demo notice |
